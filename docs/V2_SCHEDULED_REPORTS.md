# FinReview 2.x — scheduled research digests (development)

The 09:00, 12:00 and 15:00 IST worker is **not deployed or automatically scheduled**.
It is an operator-invoked CLI with a DRY RUN default. No broker orders are placed.

## Safety design

- Uses Asia/Kolkata for exact time slots, with a 5-minute late-only window.
- Fails closed on unverified market sessions: `FINREVIEW_TRADING_SESSIONS` is an
  explicit comma-separated allowlist of NSE/BSE *confirmed* open dates.
  Do not infer all weekdays are open. Holiday-calendar automation is pending.
- Sending is disabled unless the operator adds `--send` AND configures
  `FINREVIEW_V2_TELEGRAM_ENABLED=true` AND supplies private Telegram credentials.
- Each digest is claimed in the database before network transmission with a
  unique (user, trading date, slot) key.
- An ambiguous Telegram timeout is recorded as `UNKNOWN` and **not retried
  automatically** (to avoid sending duplicates). Manual reconciliation is required.
- `--send` is suitable for a private, single-user trusted environment only.
  On a shared Community deployment, isolate bot credentials and chat IDs per user.
- No exchange data is downloaded or signal generated by this worker; it
  summarizes existing account-scoped signals. Scheduling a data-refresh job and
  an official exchange-calendar integration are outstanding tasks.

## Example

Use a testing database with a real, known local user ID. The dates below are
**illustrative** and must be replaced by confirmed market-open dates, not
assumed to be actual exchange sessions.

```bash
export FINREVIEW_TRADING_SESSIONS=YYYY-MM-DD
cd backend
python -m intelligence.run_digest --user-id 1
```

On Windows PowerShell:

```powershell
$env:FINREVIEW_TRADING_SESSIONS = 'YYYY-MM-DD'
cd backend
python -m intelligence.run_digest --user-id 1
```

For a **private, authorized test only**, set the Telegram bot token and chat ID
in server-side secrets, enable `FINREVIEW_V2_TELEGRAM_ENABLED=true`, and pass
`--send`. Never commit those values or place them in CLI arguments. Live
messaging must be verified in a private staging environment before enabling it.

Running a command at the wrong time, on an unknown calendar date, or without
the explicit send flag will not deliver a Telegram message. Dry run does not
modify notification delivery records.
