# FinReview v2.0.1 — Follow-up plan

This development branch starts from the v2.0.0 Foundation Preview candidate. Do not merge into main or modify the immutable v2.0.0 tag after publication.

## Release policy — scope frozen

**Decision:** v2.0.1 is the next stable Community Edition target, not a continuous enhancement track. From this point forward, accept only defects, security fixes, migration/compatibility fixes, test coverage and documentation required to ship the existing feature set. No new strategies, dashboards, brokers, AI integrations or additional product capabilities belong in this release. Defer nonessential enhancements to a subsequent version.

**Stable Community Edition definition:** v1 portfolio/authentication workflows remain intact; the advertised v2 research UI and supported paths function end-to-end; each user can select FYERS, Upstox or Zerodha without being forced to open an account; encrypted broker secrets remain user-isolated; no real order execution; broker connectivity is never advertised as validated until live evidence exists.

**Release gates (all must pass):**
1. Green backend tests on Python 3.11 and 3.14 plus targeted security tests and no high/critical unresolved defects.
2. Clean staging deployment using a separate database; additive migration, rollback and existing v1 user/portfolio compatibility verified.
3. Authenticated multi-user isolation, OAuth callback/state replay protection, log secret redaction, stable token expiry and safe disconnect behavior tested.
4. Test real read-only historical and quote APIs with permissioned provider accounts **for every broker promoted as live-supported**. Providers not live-certified may remain in the code but must be clearly labeled **experimental/unverified and disabled for live use**. Never substitute mocked CI for real API certification.
5. Complete usable v2 frontend flow and ensure unsupported items (automatic order execution, unverified streaming, incomplete paper trading, unavailable scheduled operations) are clearly hidden/disabled or labeled experimental. No silent success or fabricated trading signals.
6. Check exchange-data licensing/entitlements, especially FYERS individual-app restrictions and Zerodha market-data subscription; no shared global token proxy on a public Community deployment.
7. Manual staging acceptance tests pass; release notes, upgrade guide, configuration/security instructions and operational rollback plan are complete.

**When all gates pass:** freeze the tested commit, merge or promote the verified release source to the deploy branch using a reviewed PR, run a final deployment smoke test, create immutable `v2.0.1` tag and publish **stable** GitHub Release (not pre-release). Stop development on this version. If a gate cannot be met, publish neither a stable release nor an unsupported readiness claim; leave it as a candidate and report only the actual blockers.

## P0: Secure broker connections
- Per-user encrypted credential vault, safe connection-status and local disconnect APIs implemented and tested. Provider-specific broker authorization-code initiation, one-time state consumption and server-side token exchange groundwork are implemented behind `FINREVIEW_V2_OAUTH_ENABLED=false`. Live account onboarding, entitlement verification, renewal, upstream revocation and key rotation remain release blockers.
- Complete optional FYERS, Upstox and Zerodha access with independent history/quote provider choices; never force one broker.
- Upstox V3 LTP quote adapter and three-broker normalized LTP snapshot interface implemented with mocked regression tests. Next: exchange timestamps, session/entitlement verification, safe per-user access and provider throttling.
- Opt-in read-only broker profile probe implemented with privacy-safe identity fingerprint and explicit UNVERIFIED data entitlement. A fail-closed, private three-part smoke check (profile, daily history, LTP quotes) is implemented with mocked tests. Real broker sessions and entitlements are NOT verified; private staging checks using permissioned accounts remain mandatory.
- A private staging-only command to check real profile + daily history + LTP entitlements is implemented and covered by mocked tests. No actual permissioned account has yet been exercised. FYERS individual apps are single-owner; a multi-user hosted deployment requires an approved provider model.
- Secret-redaction in logs and tests, clear revocation/disconnect flows, and no trading endpoints.

## P1: Production safety and data reliability
- Provider rate-limit handling, retries/circuit-breakers, per-user quotas and cache attribution.
- Trading-session calendar with official holiday checks, candle adjustment metadata, and stale-data abstention.
- Dedicated scheduled digest infrastructure; private Telegram verification and operational alerts.
- Production migration/rollback tests and separate staging environment.

## P2: Product completion
- Simulated execution costs, stops/targets, P&L and benchmark-aware paper trading.
- Finish research/paper-trading dashboard integration and support docs.

Do not claim production-ready or live broker connectivity until end-to-end tests pass.
