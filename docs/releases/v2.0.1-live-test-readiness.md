# FinReview release/2.0.1 — Private live-test gate

This document is a **test plan, not a declaration of production readiness**.

## Automated gates already covered

- Python 3.11 and 3.14 GitHub Actions regression workflows; see the branch Actions status for the final SHA.
- Broker-specific auth URLs, one-time CSRF state, replay/expiry validation and bounded pending attempts.
- Account-isolated encrypted credentials, conservative session expiry, local disconnect and no secret-bearing status responses.
- Mocked read-only profile, sample daily OHLCV and LTP checks for FYERS, Upstox and Zerodha.
- No broker order endpoints, no automatic simulated fills from unverified quotes, no browser token entry.
- Broker login routes and the live smoke command restricted to explicitly enabled STAGING.

## Private staging prerequisites (NOT satisfied automatically)

1. Create a separate staging service, URL and database. **Do not point this branch at the existing Render main deployment database or reuse its encryption keys.** Ensure database backups, HTTPS, access control and per-user isolation before enabling callbacks.
2. Supply `FINREVIEW_ENV=staging`, a staging `FINREVIEW_BROKER_VAULT_KEY`, independent `FINREVIEW_BROKER_IDENTITY_HMAC_KEY` (32+ characters), and broker app ID, client secret and exact registered HTTPS callback URL as described in `docs/V2_BROKER_SECURITY.md`. Keep all secrets in a secret manager.
3. Validate the broker's current app eligibility and consent. **FYERS individual apps support only the app creator**; do not configure one individual app as a shared third-party Community login. Zerodha's market-data entitlement may require a paid Kite Connect subscription. Upstox is optional.
4. Confirm query strings and Authorization headers are redacted from web server, reverse proxy, APM and HTTP client logs. Control who can reach the staging OAuth callback. Use the broker-approved login flow. Do not paste broker OTPs, PINs, request tokens or access tokens into chat, issues or logs.
5. Enable `FINREVIEW_V2_OAUTH_ENABLED=true` **only in staging** and begin the authenticated login process. Use the broker's own login page. Verify the broker's actual redirect/state propagation and callback response. Check `GET /v2/market/connections`: credentials should remain STORED_UNVERIFIED until independent checks pass.
6. Enable `FINREVIEW_V2_BROKER_PROBES_ENABLED=true` in a trusted staging worker and run the read-only smoke CLI. Use the broker-specific numeric instrument token for Zerodha historical requests, and exchange:tradingsymbol for Zerodha LTP. FYERS uses FYERS symbols, Upstox uses its official instrument keys.
7. Verify one recent, completed market session's daily candle and LTP quote, using the broker's official dashboard as an external point of comparison. Check timestamps, missing/partial data, token expiry, entitlement errors, rate limits and response integrity.
8. Disconnect and re-login; verify stale tokens are rejected. Try with a second FinReview account and ensure there is no cross-account data or credential access. Record results in a PRIVATE test log without account IDs or secrets.

## Run a private read-only smoke check

From the staged backend environment, after a successful approved OAuth callback and vault storage:

```bash
FINREVIEW_ENV=staging FINREVIEW_V2_BROKER_PROBES_ENABLED=true \\
python -m intelligence.staging_smoke --live \\
  --user-id 1 --broker fyers \\
  --historical-instrument NSE:INFY-EQ --quote-instrument NSE:INFY-EQ \\
  --start 2026-11-10 --end 2026-11-11
```

Dates and symbols are **examples**, not proof of a trading session or a promise that these instruments have permissioned data. Pick actual, verified symbols and recent exchange-open dates. The tool prints only profile/history/quote status and historical bar count. Failure exits nonzero. It does not modify the portfolio or place orders.

## Missing production-release gates

- Actual authorized FYERS and Zerodha login and market-data results have not yet been observed; Upstox optional live checks are also unverified.
- FYERS multi-client broker-app authorization, account-specific app configuration and exchange redistribution licensing need explicit approval.
- Provider refresh/revocation agreements, token/key rotation, complete per-user quotas and operational monitoring are not finished.
- Approved Indian exchange holiday-calendar integration and regular worker orchestration are incomplete.
- Production-grade database migrations with rollback, security/load tests, complete paper-trading accounting and full dashboard integration are not complete.
- The official v2.0.1 GitHub tag/release should **not** be created until live staging evidence and final release gates pass.

**Go/no-go:** Code with passing CI is a candidate for *private, controlled staging connectivity testing*, not for unrestricted public live brokerage use or a stable v2.0.1 release.
