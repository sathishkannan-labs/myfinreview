# FinReview v2.0.2 FYERS connection

The public demo keeps CSV and sample research available when broker access is off.
Enable the new mode only with a FYERS third-party application approved for the
intended read-only market-data use. An individual FYERS app is owner-only.

Set these on the backend after approval:

- `FYERS_CLIENT_ID` and `FYERS_APP_SECRET` from the third-party app.
- `FINREVIEW_FYERS_REDIRECT_URI` to the registered HTTPS backend callback.
  Production candidate: `https://myfinreview-api.onrender.com/v2/market/oauth/fyers/callback`.
- `FINREVIEW_FYERS_FRONTEND_RETURN_URL` to
  `https://projects.sathishkannan.com/finreview/intelligence.html`.
- `FINREVIEW_BROKER_VAULT_KEY` to an independent Fernet key.
- `FINREVIEW_FYERS_THIRD_PARTY_APPROVED=true` only after receiving written
  approval from FYERS for the intended third-party use.
- `FINREVIEW_FYERS_THIRD_PARTY_ENABLED=true` only after verifying that the app,
  backend access logs, and upstream infrastructure do not retain callback codes.

Users log in again to get a new, unique FinReview session. FYERS handles its
own login. FinReview exchanges the code server-side and uses that session's
encrypted credentials for research. Disconnect deletes the local connection.
Sign-out requests the same cleanup. Broker expiry is enforced even when local
cleanup cannot run. FinReview does not revoke credentials at FYERS.

Before publishing the integration, test two different FinReview accounts and
two sessions of one account, successful FYERS consent, a historical report,
disconnect, expiry, callback replay and broker outage with the approved app.
