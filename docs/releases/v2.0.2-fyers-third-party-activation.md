# FYERS approved third-party OAuth activation — FinReview 2.0.2

**Status: PREPARED ONLY. Keep multi-user connectivity disabled until FYERS provides written approval, permissions, and licensed market-data terms.**

This runbook covers the existing FYERS OAuth v3 code in `backend/intelligence/fyers_session.py`, `broker_oauth.py`, and `routes.py`. FinReview users authenticate **on FYERS**, never enter their FYERS password/PIN/OTP into FinReview, and receive session-scoped encrypted credentials. The app ID and secret are shared **server-side application identity**, not user input.

## Environments and operator settings

All variables below are **backend-only**. Use separate values/registrations if FYERS supports separate staging and production apps.

| Variable | Before approval | After FYERS approval |
| --- | --- | --- |
| `FINREVIEW_FYERS_THIRD_PARTY_ENABLED` | `false` | `true` only after final authorization and security tests |
| `FINREVIEW_FYERS_THIRD_PARTY_APPROVED` | `false` | `true` only with written FYERS approval recorded by the operator |
| `FYERS_CLIENT_ID` | Unset or existing individual-app value for owner-only staging | Approved third-party application ID |
| `FYERS_APP_SECRET` | Unset or existing individual-app value for owner-only staging | Approved third-party application secret |
| `FINREVIEW_FYERS_REDIRECT_URI` | Unset or owner-only registered callback | Exact FYERS-registered `https://<api-host>/v2/market/oauth/fyers/callback` |
| `FINREVIEW_FYERS_FRONTEND_RETURN_URL` | Unset | Exact HTTPS Research Lab URL ending in `/intelligence.html`, without query or fragment |
| `FINREVIEW_BROKER_VAULT_KEY` | Existing environment-specific key | Stable, backed-up Fernet key in backend secret manager; never rotate without a migration plan |
| `CORS_ALLOW_ORIGINS` | Existing allowlist | Explicitly allow the corresponding frontend origin, not `*` |
| `DATABASE_URL`, `AUTH_SECRET_KEY` | Existing per-environment values | Preserve; do not reuse staging secrets in production |

**Current staging callback route (hostname may change):**
`https://finreview-v201-staging-api.onrender.com/v2/market/oauth/fyers/callback`

**Current staging frontend return URL:**
`https://finreview-v201-staging-ui.onrender.com/intelligence.html`

These URLs are *candidate configuration values*, **not** confirmation FYERS has registered them. Do not use the individual-app secret as the third-party application secret.

Both `FINREVIEW_FYERS_THIRD_PARTY_ENABLED` and `FINREVIEW_FYERS_THIRD_PARTY_APPROVED` must be exactly `true` (case-insensitive) for multi-user mode. The availability endpoint additionally checks the app ID, app secret, callback URI, frontend return URL, and vault key; it returns only nonsecret readiness metadata. The approval flag is an **operator attestation**, not a substitute for FYERS approval.

## Activation sequence after written FYERS approval

1. Obtain and retain FYERS-approved app type, exact callback URI, market-data permissions, rate limits, redistribution rights and any restrictions on third-party usage.
2. Verify the registered HTTPS callback and frontend return URL. Confirm the Render edge/proxy and observability log policies **do not retain OAuth `auth_code`/`state` in request URLs**, or implement an approved mitigation. FastAPI `--no-access-log` alone does not cover upstream proxy logs.
3. Back up/restore the database to an isolated test instance and validate the additive `v2_fyers_sessions` schema and downgrade plan. Preserve existing portfolio data.
4. Set approved third-party application secrets in **staging** backend secret settings; leave both activation flags `false`.
5. Deploy the reviewed release commit on staging and check startup/errors, protected route authorization, two distinct accounts, logout/relogin, session expiration, disconnect, invalid/replayed state and aborted callback.
6. Once the security and licensing review is signed off, turn on both flags **in staging only**. Validate two separately authorized FYERS users with zero cross-account access.
7. Verify historical candles and quotes only within FYERS-approved usage; do not expose order endpoints, redistribute market data or imply guaranteed profitability.
8. After independent production backup/restore and release approval, repeat configuration with the production-specific app/URLs and activate production deliberately. Do not automatically enable production from the code merge.

## Fail-closed behavior / things not implemented

- Without both activation flags, a public multi-user FYERS connection is unavailable. Legacy individual-app staging owner access retains its existing separate gate.
- If third-party mode is enabled but app settings or vault key are missing, `GET /v2/market/fyers/test-availability` reports `available=false`, keeping the UI connection controls hidden.
- Tokens belong to a FinReview user and login session, are encrypted at rest, and are never returned to client JavaScript.
- `DELETE /v2/market/fyers/session` deletes local encrypted credentials only. It **does not guarantee upstream FYERS token revocation**.
- The existing token/session implementation has not yet been through an independent penetration test, third-party FYERS live acceptance or full multi-user load test.
- Backend callbacks receive query parameters. Keep production disabled until proxy-log handling is verified.
- Flag activation does not grant data licensing or regulatory permission.

## Rollback

Set `FINREVIEW_FYERS_THIRD_PARTY_ENABLED=false` and redeploy/restart the affected backend, leaving existing portfolio/transaction records untouched. Do **not** delete the session table as part of rollback. Existing broker tokens may remain stored until their expiry or explicit local disconnect; assess any immediate security incident separately.
