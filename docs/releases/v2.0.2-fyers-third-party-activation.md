# FinReview FYERS third-party OAuth — activation runbook

Status: **NOT APPROVED / NOT ENABLED** until FYERS confirms authorization in writing.

## Intended design

FinReview users sign in to FinReview, click **Connect your FYERS account**, complete authentication and consent on the official FYERS website, and return to Research Lab. One FYERS-approved **third-party app** belongs to the service; individual users do **not** enter App IDs, App Secrets, passwords, PINs, or OTPs in FinReview. Each successful connection is bound to a FinReview login/session, with FYERS tokens encrypted at rest. No real orders or account trading are supported.

The server alone performs authorization-code exchange. FYERS individual-use app credentials **must not** be used to onboard third-party customers. Obtain written approval and check data-use, market-data redistribution, and callback logging requirements first.

`FINREVIEW_V2_OAUTH_ENABLED` and `FINREVIEW_FYERS_TEST_USER_ID` belong to the legacy *individual owner-only staging test* mode; they are **not** required for the approved third-party path.

Both approval and activation gates must be `true` for the third-party mode. Turning either one off disables new sessions and research access on this path, even if encrypted credentials remain in the database. Treat the approval flag as an operator declaration: the code cannot itself verify FYERS has granted approval.

## Mandatory activation checks

1. Receive written FYERS third-party approval, confirm account types, API scopes, data rights, limits, fees and registered redirect URL.
2. Verify Render/proxy/CDN **request URL logging** does not retain OAuth `auth_code` or `state`. Application access logs are disabled, but that is not proof about upstream logs. Remediate retention or use an approved callback alternative.
3. Confirm isolated database backup/restore and existing portfolio data integrity. Ensure `v2_fyers_sessions` exists; do not use destructive migration.
4. Deploy the reviewed SHA to staging only and run Python 3.11/3.14 CI and live browser smoke checks.
5. With approved staging credentials, test two independent FYERS brokerage accounts and two FinReview users. Check OAuth state replay, wrong-user access, expired token, disconnect, quote/history errors and no order placement.
6. Confirm API/secret never appear in logs, exported JSON, browser storage, response bodies or source files.
7. Enable flags only in the authorized environment after signoff. Verify `/v2/market/fyers/test-availability` returns `THIRD_PARTY_SESSION` for authenticated users and verify no unauthorized data access.
8. Use a **separate** production change approval and post-deploy smoke test. Keep rollback switches available: set `FINREVIEW_FYERS_THIRD_PARTY_ENABLED=false` immediately if a security problem occurs.

**No public FYERS third-party access before approval.** The source-level readiness tests mock the provider; they cannot replace real broker/Render acceptance testing.
