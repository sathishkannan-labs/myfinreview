# FinReview v2.0.1 — Backend freeze and frontend acceptance contract

**Decision (15 November 2026):** Backend feature scope is frozen. No new backend strategies, broker providers, trading logic, database entities or automation for v2.0.1. Changes to backend files require a reproducible security defect, a release-blocking bug or an unavoidable compatibility dependency; document the exception with tests. The normal Community UI should expose **only supported end-to-end behavior**, not every internal endpoint.

## API-to-frontend coverage

| Backend functionality | Frontend surface | Public Community support |
|---|---|---|
| v1 auth, profile, portfolio, transactions, analytics, alerts, news, briefings | Existing `index.html` dashboard | Retained; final manual regression pending |
| `POST /v2/market/csv/research` | Research Lab: Try sample / upload daily CSV | Supported; CSV in memory, no stored prices |
| Research strategy observations (breakout/SMA/ATR) | Research Lab: evidence summary, thresholds, dates and explanations | Supported on historical validated candles only |
| Research report | Browser JSON export of backend analysis | Supported |
| `POST /v2/market/csv/validate` | Validation occurs inside research upload; separate validator not needed | Internal alternate workflow |
| `GET /v2/market/preference`, `PUT /v2/market/preference` | Maintainer diagnostics only; selector isn't a connection | Technical foundation, not advertised as live |
| `GET /v2/market/connections`, `DELETE /v2/market/connections/{provider}` | Private FYERS staging connection and local disconnect | Owner-only diagnostic |
| `/v2/market/oauth/{provider}/start`, callback | FYERS test UI, allowed for one staging owner only | No public shared broker login; other broker flows disabled |
| `POST /v2/market/fyers/test-profile`, `test-data` | Private FYERS profile/history/quote smoke buttons | Owner-only diagnostic, not a research report |
| `GET /v2/market/history`, `GET /v2/market/analyze-cached` | Not offered to public frontend | Unsafe for shared broker tokens / no populated cache workflow; remain disabled |
| `GET /v2/signals`, `GET /v2/signals/{signal_id}` | Hidden maintainer operator view | No automatic verified signal ingestion |
| `GET /v2/paper-account`, `POST /v2/paper-account` | Hidden maintainer test view | Not a completed paper trading user journey |
| Real broker order placement | None | Not implemented |

## What constitutes a usable Community Research Lab

- **No connection required:** user can click *Try sample* without downloading a file, or upload their own CSV. Upload requires signed-in FinReview authentication.
- **Complete explanation:** report shows provenance, completed-candle date coverage, latest close, SMA and breakout rules with rationale, and limitations. The summary must distinguish a historical condition from a buy/sell suggestion.
- **Evidence and export:** backend-validated result only, clear error state for invalid/missing/insufficient data, a client-side JSON download, and warning when data are stale.
- **No misleading controls:** private FYERS diagnostics, broker preferences, empty signal counters and unfinished paper ledger are hidden from ordinary accounts. Server protects the private endpoints independently of UI visibility.
- **Safety:** never present synthetic prices as real, never expose app secrets or authorization codes in frontend responses, no trades, no automatic brokerage connection, no licensed data redistribution.

## Final browser acceptance checklist

Test on separate staging Render account using test-only data:

- [ ] Login and logout; existing portfolio/transaction/analytics/news/alerts still work
- [ ] Research Lab from dashboard navigation; no experimental cards for a normal account
- [ ] Click Try sample; 65 synthetic rows analyzed and explicitly labeled as synthetic
- [ ] Upload valid user daily OHLCV; visible date range, observations and export
- [ ] Upload malformed, duplicate, current-day or insufficient-history CSV; explicit failure/insufficient-data without invented status
- [ ] Use invalid/expired session and ensure authenticated API denies uploads
- [ ] Negative second-user test: no FYERS diagnostics access, no credentials or data accessible
- [ ] Positive owner FYERS diagnostics still available only on allowlisted staging account; independently pass profile + history/quote status
- [ ] Inspect mobile layout, browser console, network errors and basic keyboard navigation
- [ ] Confirm private database isolated; migration/backup and rollback practice complete
- [ ] Verify license/use restrictions; turn off staging-only OAuth probes after tests
- [ ] Final CI green and release notes match what Community users actually receive

## Release decision

Do **not** publish `v2.0.1` until browser and safety acceptance are complete. When complete, approve the frozen tested SHA, promote via reviewed PR, run production smoke test, publish immutable stable release and stop changes. Defer all other enhancements.
