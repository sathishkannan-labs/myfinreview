# Personal FYERS staging login — v2.0.1 controlled test

**FYERS individual non-trading app only; not a public Community broker feature.**
This is a controlled personal staging test against a public Render URL. It does NOT
guarantee broker credentials are never recorded by upstream hosting edge logs.
Before a real authentication attempt, confirm Render's handling/retention of
incoming URLs and query parameters. Uvicorn app access logging is disabled in
the staging Dockerfile; upstream proxy/edge logging is outside our control.
Use a disposable/session-limited FYERS token and rotate if exposure is suspected.

## Backend setup

The separate staging backend is
`https://finreview-v201-staging-api.onrender.com`.
In its Render Environment settings, configure privately:

- `FINREVIEW_ENV=staging`
- `FINREVIEW_V2_OAUTH_ENABLED=true` **only after the above logging review**
- `FINREVIEW_FYERS_TEST_USER_ID=<your FinReview staging user numeric ID>`
- `FYERS_CLIENT_ID`, `FYERS_APP_SECRET`
- `FINREVIEW_FYERS_REDIRECT_URI=https://finreview-v201-staging-api.onrender.com/v2/market/oauth/fyers/callback`
- Independent `FINREVIEW_BROKER_VAULT_KEY` (Fernet) and
  `FINREVIEW_BROKER_IDENTITY_HMAC_KEY` (32+ characters).

Find your numeric FinReview *staging account* ID by logging into the
staging dashboard and inspecting the `finreview_user_id` localStorage value in
your own browser DevTools; **do not share an auth bearer token**. This ID is
not a FYERS account number. The allowlist fails closed when absent, nonnumeric,
or zero. Only the owner user can start a login. Do not enable login on the
production Render workspace or reuse its secrets.

## Human test

1. In your separate Render staging account, confirm the latest backend/frontend
   deployments both show Live and `release/2.0.1`.
2. Login at the staging frontend with your staging FinReview account.
3. Open Research Lab > Experimental tools & broker settings > FYERS personal app.
4. Confirm the availability message enables **Connect FYERS**. If not, inspect
   the allowlist/flag; do not post secrets in support channels.
5. Select Connect FYERS and finish on the official `api-t1.fyers.in` login
   page with the app creator's FYERS credentials. The pending state expires
   after five minutes. Do not forward the callback URL or post screenshots
   containing `auth_code` or `state`.
6. On the callback result page, confirm encrypted storage **or** a generic failure
   message. Return manually to the Research Lab and refresh connection status.
7. Select **Test read-only profile** to check actual authentication. A positive
   profile result does **not** validate market-data entitlements.
8. Select Disconnect locally and verify no FYERS connection records remain.
   Local deletion is not broker-side token revocation. Disable OAuth when done.

## Threat model and limitations

- App auth-code exchange is server-to-server, one-time state with 5-minute expiry;
  no raw credential input is accepted by FinReview frontend.
- Callback produces a static HTML page, no token, state or code in its response,
  no reflected inputs, no query-bearing redirect, no external resources and
  Cache-Control no-store.
- Uvicorn is run with `--no-access-log`, limiting application-side access
  log leakage, **not Render edge logging**.
- The FYERS individual app can only authorize its creator; this path is
  allowlisted to one FinReview staging user ID.
- The first profile probe is read-only. FYERS quotes/history entitlement,
  session refresh, token rotation, proxy log retention and independent
  multi-user security review remain unverified.
- Do not turn on `FINREVIEW_V2_MARKET_API_ENABLED` to expose process-wide
  FYERS credentials as a shared public quote API.
- Never change production settings or consider this a stable Community Edition
  deployment without separate acceptance.

To stop this test immediately, set `FINREVIEW_V2_OAUTH_ENABLED=false`,
then disconnect the test user and rotate/revoke at FYERS as needed.
